Claude Code를 쓰다 보면 "토큰 제한에 걸렸다", "Claude가 같은 코드를 반복한다", "갑자기 바보가 됐다" 같은 경험을 하게 됩니다. 이 모든 현상의 원인은 **토큰**과 **컨텍스트 윈도우**에 있습니다.

이 페이지는 토큰이 뭔지부터 시작해서, 왜 관리해야 하는지, 어떻게 효율적으로 쓰는지를 정리합니다.

---

## 토큰이란?

AI가 데이터를 처리하는 **최소 단위**입니다.

사람은 글자나 단어를 세지만, AI는 토큰 단위로 읽고 생성합니다.

| 입력 | 토큰 수 |
|------|--------|
| "Hello" | 약 1개 |
| "안녕하세요" | 약 5개 |

> 한국어는 영어보다 같은 의미에 더 많은 토큰을 사용합니다.

### 토큰의 크기는 고정이 아닙니다

같은 문장이라도 **모델에 따라 토큰 수가 달라질 수 있습니다.** 각 모델은 자체 토크나이저를 사용하기 때문입니다.

---

## 입력 토큰과 출력 토큰

Claude와의 모든 상호작용은 토큰으로 측정됩니다.

| 종류 | 포함되는 것 |
|------|-----------|
| **입력 토큰** | 내가 보내는 메시지, 첨부 파일 내용, 대화 히스토리, CLAUDE.md 등 컨텍스트 |
| **출력 토큰** | Claude가 생성하는 응답, 코드, 설명, 분석 결과 |

대화를 주고받을수록 **토큰은 계속 쌓입니다.**

---

## 컨텍스트 윈도우

컨텍스트 윈도우는 **한 번에 처리할 수 있는 최대 토큰 사용량**입니다.

비유하면 **책상 위의 공간**과 같습니다. 책상이 꽉 차면 새 자료를 놓기 위해 기존 자료를 치워야 합니다.

| 모델 | 컨텍스트 윈도우 |
|------|---------------|
| 기본 (Sonnet, Opus) | 200K 토큰 |
| 확장 모델 (`opus[1m]`, `sonnet[1m]`) | 1M 토큰 |

컨텍스트 윈도우가 200K라는 건, **입력 + 출력을 합쳐서 최대 200K까지 쓸 수 있다**는 뜻입니다.

### 컨텍스트가 차면 무슨 일이 생길까

- Claude가 이전에 준 **지시를 잊기 시작**합니다
- **같은 실수를 반복**하거나, 같은 코드를 다시 제안합니다
- 응답 품질이 눈에 띄게 **떨어집니다**

> "Claude가 바보가 됐다"고 느끼면, 대부분 컨텍스트가 꽉 찬 상태입니다.

### 컨텍스트를 차지하는 것들

Claude에게 프롬프트를 보낼 때, 눈에 보이는 것만 전송되는 게 아닙니다.

| 항목 | 토큰 사용 |
|------|---------|
| 시스템 프롬프트 | ~4,200 |
| CLAUDE.md | ~2,000 |
| 서브에이전트, MCP 도구 목록 | 수백~수천 |
| 파일 읽기 (한 번에) | 1,000~3,000 |
| 명령어 출력 (npm test 등) | 수백~수천 |
| Claude의 응답 | 수백~수천 |

> **서브에이전트, MCP, CLAUDE.md 모두 컨텍스트를 차지합니다.** 너무 많이 설치하면 Claude가 바보가 될 확률이 높아집니다. 정말 필요한 것만 남기고, 안 쓰는 건 과감히 제거하세요.

## 컨텍스트 관리 명령어

### 새로운 작업을 시작할 때 → /clear

```
/clear
```

이전 대화가 쌓이면 불필요한 토큰이 누적됩니다. 새 작업을 시작할 때는 항상 컨텍스트를 초기화하세요.

### 작업을 이어가고 싶은데 컨텍스트가 거의 찼을 때 → /compact

```
/compact
```

메시지를 압축해서 공간을 확보합니다. 대화의 맥락은 유지하면서 토큰만 줄입니다.

집중해서 보존할 내용을 지정할 수도 있습니다:

```
/compact 수정한 파일 목록과 테스트 결과에 집중해
```

> 더 자세한 내용은 [컨텍스트(토큰) 최적화]({{< relref "context-optimization" >}}) 페이지를 참고하세요.

## 사용량 제한

토큰은 **비용**이자 **사용량 제한**입니다.

### 사용량 확인

```
/usage
```

현재 사용량을 바로 확인할 수 있습니다.

### 사용량 차감 방식

모든 모델이 동일하게 차감되지 않습니다.

| 모델로 작업 | 현재 세션 | 주간 전체 모델 | 주간 해당 모델 |
|-----------|---------|-------------|-------------|
| Opus | 차감 | 차감 | 영향 없음 |
| Sonnet | 차감 | 차감 | 차감 |
| Haiku | 차감 | 차감 | 영향 없음 |

> Sonnet으로 작업하면 "주간 Sonnet 전용" 한도도 차감됩니다. Opus나 Haiku는 전체 한도만 차감합니다.

### 사용량 제한에 걸리면

- 응답이 느려지거나, 일시적으로 사용이 제한됩니다
- 5시간 제한과 7일 제한 두 가지가 있습니다
- [상태 표시줄]({{< relref "statusline" >}})에 `rate_limits` 필드를 표시하면 실시간으로 확인 가능합니다

## 토큰 효율화 핵심 3가지

### 1. 명확한 프롬프트로 범위 제한

Claude에게 모호한 지시를 하면 여러 파일을 읽고 넓은 범위를 탐색합니다. 그만큼 토큰을 많이 씁니다.

| 방식 | 프롬프트 | 토큰 사용 |
|------|---------|---------|
| 모호함 | "인증 관련 코드 살펴봐" | 많음 (여러 파일 탐색) |
| 명확함 | "src/auth/token.ts의 refreshToken 버그 수정해" | 적음 (필요한 파일만) |

범위를 좁히는 핵심 키워드:

| 키워드 | 예시 |
|--------|------|
| "간단한" | "간단한 상품 목록 페이지를 만들어줘" |
| "단일 파일로" | "단일 HTML 파일로만" |
| "~줄 이하" | "200줄 이하로" |
| "제외" | "배포/테스트/빌드 제외" |

### 2. 작업에 맞는 모델 선택

| 상황 | 추천 모델 |
|------|----------|
| 학습, 간단한 실습 | Haiku — 빠르고 토큰 효율 최고 |
| 일상적인 코딩 | Sonnet |
| 복잡한 프로젝트, 실전 개발 | Sonnet 또는 Opus |
| 계획은 정확하게, 실행은 효율적으로 | opusplan |

> Haiku를 적극 활용하세요. 간단한 질문, 코드 설명, 학습용 실습에는 Haiku면 충분합니다. `/model haiku`로 전환합니다.

### 3. 컨텍스트를 깨끗하게 관리

| 상황 | 행동 |
|------|------|
| 새 작업 시작 | `/clear` |
| 작업 이어가기 + 공간 부족 | `/compact` |
| 조사가 필요한 작업 | 서브에이전트에 위임 |
| 안 쓰는 MCP 서버 | `/mcp`에서 비활성화 |
| CLAUDE.md가 200줄 이상 | 불필요한 내용 정리, Skill로 분리 |

---

## 정리

> **AI 네이티브 개발자가 되려면, 결국 컨텍스트 싸움입니다.**

이 원칙들은 Claude Code뿐만 아니라 모든 AI 모델에 동일하게 적용됩니다. AI 모델이 더 똑똑해지고 컨텍스트 윈도우가 더 커지더라도, **컨텍스트를 효과적으로 관리하는 것**이 AI를 잘 활용하는 핵심입니다.

| 원칙 | 실천 |
|------|------|
| 명확한 프롬프트 | 범위를 좁히고, 구체적으로 지시 |
| 적절한 모델 | 간단한 건 Haiku, 복잡한 건 Opus |
| 깨끗한 컨텍스트 | `/clear`와 `/compact`를 습관처럼 사용 |
