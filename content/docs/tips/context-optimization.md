Claude Code의 컨텍스트 윈도우는 대화, 파일 읽기, 명령어 출력 등으로 빠르게 찹니다. **컨텍스트가 차면 성능이 떨어집니다.** 이전 지시를 잊거나, 같은 실수를 반복하기 시작합니다.

컨텍스트는 Claude Code에서 가장 중요한 자원입니다.

---

## 컨텍스트가 채워지는 순서

세션이 시작되면 아래 항목들이 자동으로 로드됩니다.

| 순서 | 항목 | 대략적 토큰 |
|------|------|------------|
| 1 | 시스템 프롬프트 | ~4,200 |
| 2 | Auto Memory (MEMORY.md) | ~680 |
| 3 | 환경 정보 (OS, 디렉토리, git 상태) | ~280 |
| 4 | MCP 도구 이름 목록 | ~120 |
| 5 | Skill 설명 목록 | ~450 |
| 6 | `~/.claude/CLAUDE.md` | ~320 |
| 7 | 프로젝트 `CLAUDE.md` | ~1,800 |

이후 대화를 시작하면:

- **파일 읽기**가 컨텍스트를 가장 많이 차지합니다. 파일 하나에 1,000~3,000 토큰
- **명령어 출력** (`npm test` 등)도 수백~수천 토큰
- **Claude의 응답**도 컨텍스트에 쌓입니다
- **후속 질문**을 할수록 계속 누적됩니다

> 파일 읽기 한 번이 프롬프트 수십 개보다 컨텍스트를 많이 씁니다.

---

## 핵심 명령어 4가지

### /context — 현재 상태 확인

컨텍스트가 얼마나 찼는지 색상 격자로 시각화합니다.

```
/context
```

무엇이 컨텍스트를 많이 차지하는지, 최적화할 부분이 있는지 제안도 함께 보여줍니다. 작업 중간에 "좀 느려진 것 같다" 싶으면 먼저 실행하세요.

### /clear — 컨텍스트 완전 초기화

대화 기록을 모두 지우고 새 세션을 시작합니다.

```
/clear
```

이전 세션은 사라지지 않습니다. `/resume`으로 언제든 돌아갈 수 있습니다.

**언제 쓸까:**
- 다른 주제로 넘어갈 때
- 같은 수정을 2번 이상 지시했는데 고쳐지지 않을 때 (컨텍스트가 실패한 시도로 오염됨)
- "잘 안 된다" 싶을 때 가장 먼저 시도

### /compact — 대화 요약으로 컨텍스트 확보

대화 내용을 요약해서 컨텍스트를 줄입니다. 대화의 흐름은 유지하면서 공간만 확보합니다.

```
/compact
```

요약 시 **무엇에 집중할지** 지시할 수도 있습니다:

```
/compact 코드 변경사항과 테스트 결과에 집중해
/compact API 엔드포인트 변경 내역만 남겨
/compact 수정한 파일 목록과 커밋 메시지를 보존해
```

CLAUDE.md에 기본 요약 지침을 넣어둘 수도 있습니다:

```markdown
# Compact instructions
When you are using compact, please focus on test output and code changes
```

### /compact vs /clear

| | `/compact` | `/clear` |
|--|-----------|---------|
| 대화 내용 | 요약해서 남김 | 완전히 지움 |
| 작업 연속성 | 유지됨 | 끊김 |
| 컨텍스트 절약 | 부분적 | 완전 |
| 추천 상황 | 같은 작업을 계속할 때 | 다른 주제로 넘어갈 때 |

## /rewind — 부분 되감기

대화의 특정 시점을 선택해서 **그 지점부터 요약**할 수도 있습니다.

```
Esc + Esc  또는  /rewind
```

메시지 체크포인트 목록이 뜨면, 원하는 지점을 선택하고 **"Summarize from here"**를 고릅니다. 선택한 시점 이후의 대화만 요약되고, 그 전의 컨텍스트는 그대로 유지됩니다.

전체를 요약하는 `/compact`와 달리, 특정 구간만 정리할 때 유용합니다.

## Auto-Compact 설정

`/config`에서 Auto-Compact를 설정할 수 있습니다.

```
/config → Auto-Compact
```

| 설정 | 동작 |
|------|------|
| 켜짐 (기본) | 컨텍스트가 한계에 가까워지면 자동으로 요약 |
| 꺼짐 | 수동으로만 `/compact` 실행 |

Auto-Compact가 켜져 있으면 Claude Code가 알아서 대화를 요약하므로 대부분의 경우 수동 개입이 필요 없습니다. 하지만 **중요한 지시가 요약 과정에서 사라질 수 있으므로**, 핵심 규칙은 CLAUDE.md에 넣어두는 것이 안전합니다.

### Compaction 후 보존되는 것

| 항목 | compaction 후 |
|------|---------------|
| 시스템 프롬프트 | 그대로 유지 |
| CLAUDE.md (루트) | 그대로 유지 (재로드) |
| `~/.claude/CLAUDE.md` | 그대로 유지 (재로드) |
| `.claude/rules/` (경로 규칙) | 요약됨. 해당 파일을 다시 읽으면 재로드 |
| Skill 본문 | 사용한 것만 재주입 (오래된 것부터 제거) |
| Skill 설명 목록 | 재로드되지 않음 |
| Hook | 코드로 실행되므로 영향 없음 |

> 경로별 규칙(`.claude/rules/`)은 compaction 시 요약됩니다. 항상 유지해야 하는 규칙은 프로젝트 루트 CLAUDE.md에 넣으세요.

## 실전 시나리오: 코딩 세션 흐름

### 1. 새 작업 시작

```
/clear
```

이전 작업의 컨텍스트를 비우고 깨끗하게 시작합니다. 전환 전에 `/rename auth-refactor`로 이름을 붙여두면 나중에 찾기 쉽습니다.

### 2. 작업 진행

프롬프트를 구체적으로 작성해서 불필요한 파일 읽기를 줄입니다.

```
❌ "인증 관련 코드를 살펴봐"  →  많은 파일을 읽음
✅ "src/auth/token.ts에서 refreshToken 함수의 버그를 고쳐"  →  필요한 파일만 읽음
```

조사가 필요하면 서브에이전트에 위임합니다:

```
서브에이전트를 사용해서 인증 시스템의 토큰 갱신 흐름을 조사해줘
```

서브에이전트는 별도 컨텍스트에서 파일을 읽고, 요약만 메인 컨텍스트에 돌려줍니다.

### 3. 중간 점검

```
/context
```

컨텍스트 사용량을 확인합니다. 절반 이상 찼다면 요약을 고려합니다.

### 4. 컨텍스트 정리

같은 작업을 계속한다면:

```
/compact 수정한 파일과 남은 작업에 집중해
```

다른 작업으로 넘어간다면:

```
/rename token-refresh-fix
/clear
```

### 5. 반복

이 흐름을 반복합니다. `/clear`를 자주 쓰는 것이 핵심입니다.

## 컨텍스트 절약 팁 모음

| 방법 | 효과 |
|------|------|
| `/clear`로 주제 전환 시 초기화 | 매 메시지마다 처리하는 토큰 감소 |
| 프롬프트를 구체적으로 작성 | 불필요한 파일 읽기 방지 |
| 조사는 서브에이전트에 위임 | 파일 내용이 메인 컨텍스트에 안 쌓임 |
| `/compact` 시 집중 지시 추가 | 중요한 내용이 요약에서 보존됨 |
| `/btw`로 사이드 질문 | 대화 기록에 남지 않아 컨텍스트를 안 씀 |
| CLAUDE.md 200줄 이하 유지 | 매 세션 로드 토큰 절약 |
| 자세한 워크플로우는 Skill로 분리 | 호출 시에만 로드, 평소엔 설명 한 줄만 |
| 사용 안 하는 MCP 서버 비활성화 | `/mcp`에서 확인 후 끄기 |

## 경고 신호

아래 증상이 나타나면 컨텍스트를 정리할 때입니다.

- Claude가 이전에 준 지시를 잊기 시작함
- 같은 실수를 반복함
- 응답이 느려짐
- "Conversation compacted" 메시지가 자동으로 뜸 (Auto-Compact 발동)

> 2번 이상 수정 지시를 했는데 고쳐지지 않으면, `/clear` 후 배운 점을 반영한 더 구체적인 프롬프트로 새 세션을 시작하세요. 깨끗한 컨텍스트 + 좋은 프롬프트가 오염된 긴 세션보다 항상 낫습니다.
